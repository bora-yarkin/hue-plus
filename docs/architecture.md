# Architecture

One config entry per Hue bridge. The entry's `Runtime` (`runtime.py`) holds the Hue entry it rides on, the modules switched on
for it, and what each module keeps while running.

```
custom_components/hue_plus/
  __init__.py  config_flow.py  const.py  runtime.py     entry setup, options, constants
  connection.py  coordinator.py  entity.py  platform.py shared: the Hue connection, one bridge read, entity bases
  services.py  services_base.py  spec.py  fieldspec.py  one description of every service, schemas built from it
  <platform>.py                                         thin: hand the platform to each module that is on
  bridge/  lights/  devices/  zones/  sync/  streaming/  the modules
  scene_import.py                                        reads a Hue scene for Home Control (no module)
  strings.json  translations/  services.yaml            generated by scripts/generate_services.py
```

**Connection.** `link.BridgeLink` is how an entry reaches its bridge: through the Hue integration's connection, or `direct.DirectBridge` (aiohue's client with the certificate
pinned). Everything else asks the link for the bridge object, the address and the key and never needs to know which it is.

**Layering rule.** In each module, files that import nothing from Home Assistant (`api`, `models`, `payloads`, `actions`,
`client`, `engine`, `library`, ...) hold the logic and are tested on their own (`tests/support.py` loads them as a separate
package so an accidental Home Assistant import fails the tests). Files named after a platform, `services.py`, `setup.py`,
`coordinator.py` and `entity.py` are the Home Assistant layer.

**Services.** Each module has a `spec.py` (fields, descriptions); `spec.py` at the root merges them. `services.yaml`,
`strings.json` and `translations/en.json` are generated from the merged spec and a test fails when they are stale.

**Lights.** `lights/light.py` subclasses the Hue integration's own `HueLight` and `GroupedHueLight` onto Hue Plus's devices, so
every feature of those lights is inherited and follows Home Assistant's changes. `lights/adopt.py` hides the Hue integration's
light entities and renames them with `_hue` so Hue Plus's lights get the names; it gives them back (`async_release`) when the
module is switched off or the entry is removed. The long-term plan is to copy the code out of the Hue integration and drop the
dependency on its connection.

**Devices.** `devices/core.py` runs the Hue integration's own platform setups (`binary_sensor`, `event`, `scene`, `select`,
`sensor`, `switch`) with Hue Plus's config entry (a small proxy gives them Hue's connection and Hue Plus's lifetime) and moves
each entity onto the matching Hue Plus device (`rehome`). Nothing of those platforms is copied, so every feature comes along;
the entities of the Hue integration are hidden and renamed first (`adopt`), as for the lights. One thing does not come along by itself:
the Hue integration's scene action `activate_scene` (live, with a speed, a brightness and a fade) is registered for the `hue` platform's
own entities since Home Assistant 2026.11 (before, its scene platform registered it for whatever platform ran it), so `devices/scene.py`
registers `hue_plus.activate_scene` with the same options when the platform has not. The dashboard starts a Hue scene with it.

**Home Control (decision D-25).** The dashboard pages of Hue Plus are Hue Plus's: `frontend/src` (the Hue Plus menu, the bridge-area import and editing, Hue's scenes, the Spotify sync and sync box, the gradient styles, the adapter that reads what Hue Plus offers, the texts and the styles of the sync popups) is built into `custom_components/hue_plus/frontend/menu.js`, served at `/hue_plus_static/menu.js` and loaded by Home Control for administrators.  Live scenes and areas are played by Home Control, for any light. Hue Plus is the expansion pack for Hue lights: `home_control.json`
declares the Hue lights it owns (their entity platforms, the bridge's command rate) and the native effects it can play, and `hue_plus.play_effect` (an action on
Hue Plus's light entities, `lights/light.py`) plays one of a light's own effects with a colour through the bridge. Nothing is imported in either direction. The scenes module that
played live scenes here was removed in 0.8.0 (HP-12.3); the scenes and areas it saved stay in its storage file, which Home Control took over once.


## Spotify Sync authentication

The bridge config entry holds a manual access token or a reference to Home Assistant Application credentials and the
developer OAuth token pair. Both modes supply the same UUID and access token to the Home-Assistant-free Sync client.
The OAuth provider renews before a connection opens. An open socket gets a renewal deadline and reconnects when it is
reached. Only the Sync connection changes on rotation. Bridge and Sync Box registrations follow their own flows.
